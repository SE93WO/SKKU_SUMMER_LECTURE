----------------------------------------------------------------
1. 개요
----------------------------------------------------------------

- 내용: 포르투갈 Montesinho 공원 산불 517건의 기상·피해 기록
- 출처: UCI #162 (Cortez & Morais, 2007), 2000~2003 수집
- 규모: 517행 · 13열 · 결측 없음
- 유형: 회귀 (소실 면적 예측)
- 예측 대상: area (헥타르)
- 특징: UCI가 "어려운 회귀 과제"로 명시 — 5절·참고


----------------------------------------------------------------
2. 왜 이 문제인가
----------------------------------------------------------------

- 산불 규모 예측 → 진화 자원 배치·사전 배치
- 쉽게 얻는 기상 자료만으로 예측 가능한지 검증
- 강의 사례 연결: 17p 기후 재해 탐지, 52p PM2.5
- 교육적 가치: "데이터에 신호가 없으면 어떤 모델도 답 못 냄"
  → 지금까지와 달리 예측이 잘 안 되는 경험


----------------------------------------------------------------
3. 컬럼 구성
----------------------------------------------------------------

[ 공간·시간 ]
- X, Y                공원 격자 좌표 (X 1~9, Y 2~9)
- month              월 ("jan"~"dec")
- day                요일 ("mon"~"sun")

[ 화재기상지수 (FWI, 기상값에서 계산된 파생) ]
- FFMC               미세연료 습도
- DMC                부식층 습도
- DC                 가뭄 지수
- ISI                초기 확산 지수

[ 기상 원시값 ]
- temp               기온 · RH 습도 · wind 풍속 · rain 강우

[ 예측 대상 ]
- area               소실 면적 (헥타르)

5. 주의 — 그냥 넣으면 문제 되는 것 (해결 코드 포함)
----------------------------------------------------------------

[ 오류는 없지만 잘못 학습되는 것 ]

① target(area) 약 절반이 0 (247/517 = 47.8%)
   증상: 0은 결측 아님(0.1ha 미만 = 작은 불).
         모델이 "대체로 0" 학습 → 큰 불을 못 맞힘
   해결 (분류로 바꾸거나, 0 제외 후 회귀):
        # 큰 불 여부 이진 분류
        df["big_fire"] = (df["area"] > 0).astype(int)

② target 분포 극단적 치우침 (0 ~ 1090)
   해결 (로그 변환, 0 많으니 log1p):
        import numpy as np
        df["log_area"] = np.log1p(df["area"])
        # 예측값은 np.expm1로 되돌려 비교

③ X, Y는 숫자로 코딩된 위치 (X 1~9, Y 2~9)
   증상: X=9가 X=1의 9배로 오해될 수 있음
   해결 (범주형 — 다만 수치형이 나을 수도, 비교):
        df["X"] = df["X"].astype("category")
        df["Y"] = df["Y"].astype("category")

④ FWI 지수 vs 원시 기상값 정보 중복
   증상: FFMC/DMC/DC/ISI는 기상값에서 계산됨 → 상관 높음
   해결: 세 조합으로 비교 (전부 / FWI만 / 기상값만)


[ EDA / 판단 참고 ]

⑤ rain 거의 전부 0 → 정보 거의 없음. 제거 검토
⑥ 평가용 20%가 103건뿐 → 성능 불안정
   → random_state 바꿔가며 여러 번 확인
⑦ 성능이 낮게 나오는 게 정상. 원인이 데이터(신호 부족)일 수
   있음 → 모델 교체가 답이 아닐 수 있다
